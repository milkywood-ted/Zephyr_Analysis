# Zephyr RTOS 커널 코어 분석

Zephyr RTOS의 커널 코어를 소스 코드 수준에서 분석한 문서 모음입니다. 모든 서술은 실제 소스의 `파일:행`을 근거로 제시하며, 코드에서 직접 확인한 사실과 추론을 구분합니다.

## 분석 대상

| 항목 | 값 |
|---|---|
| 프로젝트 | [Zephyr RTOS](https://github.com/zephyrproject-rtos/zephyr) |
| 버전 | **4.4.99** (4.4 릴리스 이후 `main` 계열 개발 스냅샷) |
| SDK | 1.0.1 |
| 빌드 타깃 | `qemu_cortex_a53` SMP 변형 (ARM Cortex-A53 / AArch64, 2코어) |
| 보조 타깃 | Cortex-M 계열 (`CONFIG_SWAP_NONATOMIC` 경로 확인 전용) |

타깃을 Cortex-A53 SMP로 잡은 이유와 확정된 커널 구성은 [00-분석-개요.md](00-분석-개요.md) §4에 정리되어 있습니다. 요약하면, ARM64가 `CONFIG_USE_SWITCH`를 무조건 select하므로 신형 컨텍스트 스위치 경로가 전부 실코드이고, 같은 보드에 UP/SMP 두 변형이 있어 두 경로를 대조할 수 있으며, QEMU 보드라 실물 하드웨어 없이 검증이 가능하기 때문입니다.

### 읽는 순서

번호 순서(00 → 07)를 권합니다. 01의 자료구조를 알아야 02의 스케줄러 코드가 읽히고, 02·03이 참조하는 타임아웃 메커니즘이 04에서, 두 문서가 이름만 언급하고 넘어간 스핀락과 IPI가 05에서 확정됩니다. 07은 앞의 전부가 어떻게 조립되는지를 보여주므로 마지막에 읽는 편이 낫습니다.

특정 주제만 필요하다면:

- **컨텍스트 스위치가 어떻게 일어나는가** → 02 §7
- **SMP에서 실행 중인 스레드를 어떻게 안전하게 중단하는가** → 03 §7
- **깨우는 쪽과 타임아웃 핸들러의 경합을 어떻게 푸는가** → 04 §6
- **스핀락이 왜 인터럽트를 먼저 잠그는가** → 05 §2.2
- **IPI를 왜 모았다가 한 번에 보내는가** → 05 §6
- **뮤텍스 우선순위 상속이 어디까지 전파되는가** → 06 §4

## 문서 규약

- **근거 제시**: 모든 서술에 `파일:행` 링크를 답니다. 행 번호는 분석 시점의 작업 트리 기준이며, 상류 소스가 갱신되면 어긋날 수 있습니다.
- **확신도 표기**: 코드에서 직접 확인한 사실과 추론을 구분하고, 추론에는 `(확신도: high / medium / low)`를 붙입니다.
- **타깃 적용표**: 각 문서 상단에 "이 타깃에서 어느 코드가 활성/비활성인가"를 표로 제시합니다. `#ifdef`가 많은 커널이므로, 읽고 있는 코드가 실제로 컴파일되는지 아는 것이 중요합니다.
- **원본 무수정**: 이 저장소는 분석 문서만 담습니다. Zephyr 소스는 수정하지 않습니다.

## 저장소 구성과 소스 경로

이 저장소에는 **분석 문서만** 들어 있습니다. Zephyr 소스는 west 워크스페이스의 형제 디렉터리에 있으며, 문서가 참조하는 경로는 **워크스페이스 루트 기준**입니다.

```
<west workspace>/
├── zephyr/            # Zephyr 소스 (분석 대상, 별도 git 저장소)
├── modules/           # west 관리 모듈
├── bootloader/
├── tools/
└── 1.zephyr분석/      # ← 이 저장소
```

따라서 문서 안의 `zephyr/kernel/sched.c` 같은 경로는 이 저장소가 위 배치의 워크스페이스 안에 있을 때 해석됩니다.

> **알려진 제약**: 현재 문서의 소스 링크는 워크스페이스 루트 기준이라 저장소 단독으로는(예: GitHub 웹) 해석되지 않습니다. 해소 방안은 아래 "향후 작업"을 참조하십시오.

## 분석의 한계

커널 구성은 Kconfig의 `select`/`default` 선언과 보드 defconfig에서 도출했습니다. `select`로 강제되는 항목(`USE_SWITCH`, `SMP`, `SCHED_IPI_SUPPORTED` 등)은 빌드 없이도 확실하지만, **기본값에 의존하는 항목은 상위 Kconfig가 덮어쓸 여지가 이론상 남습니다.** 해당 서술에는 확신도 `medium`을 표기해 두었습니다. 상세는 [00-분석-개요.md](00-분석-개요.md) §4.4를 참조하십시오.

이는 정적 분석의 고유한 한계이며, **한계를 명시한 것으로 분석은 완결된 것으로 봅니다.** 직접 확인하고 싶다면 Zephyr SDK 설치 후 아래 산출물과 [00-분석-개요.md](00-분석-개요.md) §4.2의 표를 대조하면 됩니다.

```sh
west build -b qemu_cortex_a53/qemu_cortex_a53/smp samples/hello_world
# build/zephyr/.config
```
